### Notes on M2-01 and M2-02 (fix direction, not applied)
- M2-01: add `0100…0080` and `ecff…ffff` to `SMALL_ORDER`. More robustly, reject any encoding whose x = 0 with the sign bit set. Add vectors for both as buyer key (`schema`) and as R (`bad_signature_encoding`), plus the forgery vector, which must be `schema` in both.
- M2-02: make the two sides use the same equation. One way is a prime-order subgroup check ([L]P = identity) on A and R in both guards. Another is to verify cofactorless in TypeScript, either by comparing R bytes with `encode(SB - kA)` or with a dalek-compatible verifier. Add the two exploit inputs as shared vectors.
- **Assumption:** severity of M2-01 is High because R1 is bypassed in the code path the contract will run. Direct loss of funds depends on M3: whether any authority (refund, purchase as buyer, deposit attribution) attaches to the buyer key. If none does, the owner may downgrade it to Medium.

### Items checked with no finding
- NEP-413 payload layout (tag 2^31+413 LE, borsh message, nonce = `mandate.nonce`, recipient = `mandate.gate`, `callback_url` None) is identical on both sides. Replay across network, gate, nonce and amount is covered by vectors. `v` is inside the signed mandate.
- ERC-191: prefix uses the byte length; v ∈ {0, 1, 27, 28}; r and s in [1, n-1]; low-s with s = n/2 allowed; the address comes from the recovered key. Differential testing agreed on 1,200 random signatures.
- Canonical JSON: UTF-16 key order, escapes, control characters, `\/`, surrogate pairs, BOM, the number scan (including escapes before quotes), depth, and the size limit checked before parsing. All agree apart from M2-06.
- Grammars (account, amount, `time_ns`, hex32, item, network, base58 with canonical re-encode, EVM): the Rust hand-written parsers match the TypeScript regexes, and differential fuzzing found no mismatch.
- Receipt core: rule order, closed objects, `decision` iff all pass. The check order (and so the error code) is the same in both languages.
- Vectors hold only public keys and signatures. No signature pair in them reuses a nonce across different messages, so no key can be recovered from the vectors themselves. M2-05 concerns the generator, not the vectors.
- No test passes vacuously: unknown vector kinds throw in TypeScript and panic in Rust, and every vector compares both the hash and the error code. Changes to existing tests (`scripts/tests/*`) do not weaken any check.
