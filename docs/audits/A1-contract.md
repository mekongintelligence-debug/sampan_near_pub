Date: 6-7 November 2026 (resumed after a container restart; the runs stopped by the restart were re-run or had already finished) · Auditor session: fresh Claude Code subagent with no author context and no context from the other A1 session (A1-payments). It runs inside the cloud session `session_01CRNp9dXNNRsXBgwWH9ULTZ`, which also appears on the author's commits. `docs/MILESTONES.md` says A1 runs "in a separate Claude Code session", so the security owner should decide whether this run counts as one. The in-scope files are identical at `ed5627b`, the head of `claude/practical-knuth-g21soa` when this audit ran (`git diff 51dac1d ed5627b -- contracts crates scripts/m3 scripts/m4 apps/agent-demo` is empty).

Scope: `contracts/gate/**` (`lib.rs`, `rules.rs`, `tests.rs`, `tests/*.rs`, `Cargo.toml`), `crates/formats/**` (canonical JSON, grammars, mandate and order parsing, NEP-413 and ERC-191 verification, receipt core, fuzz targets), the agent key design (`apps/agent-demo/src/*`, `scripts/m4/*`), and the testnet deploy and init scripts (`scripts/m3/*.mjs`), read as the basis for the mainnet deploy. Goals: S1 (funds only to the signed payee within budget), S2 (refunds only to `refund_to`), S3 (the agent key reaches `purchase` and nothing else), S4 (every decision anchored, no lying receipt), S6 (no off-chain text changes a decision).

Purpose (`docs/MILESTONES.md`, A1): no Critical or High issue may remain in the contract before real money touches it. This report blocks every mainnet step until the security owner signs it.

## Method
- Read `CLAUDE.md`, `docs/SECURITY.md` (all), `docs/ARCHITECTURE_AND_PLAN.md` 3.4 with "As built in M3", `docs/FORMATS.md`, `docs/gates.md`, `docs/m3-testnet.md`, `docs/m4-testnet.md`, and `docs/audits/M3.md` and `M4.md`. Treated every "fixed" claim as a claim to verify.
- Audited a detached worktree of `51dac1d` (`git worktree add /tmp/a1c 51dac1d`). Read `lib.rs` and `rules.rs` line by line, and all of `crates/formats/src`. For each public method (`new`, `ft_on_transfer`, `purchase`, `on_payout`, `refund`, `on_refund`, views), asked what each attacker can do with any arguments, in any order, with any gas, and between a release and its callback. Attackers: a stranger, a malicious or injected agent, a fake token, the token contract itself, a malicious payee (including one that reverts or re-enters), and the 1Click delivery path (`ft_transfer_call` with `msg`).
- Checked near-sdk 5.30.1 behaviour in its source: `promise_result_checked` (`Failed` vs `TooLong`), `Promise::function_call` (static gas, no weight) against the `ext` callback builder (`GasWeight::default()` = 1, so the callback also gets the unused gas), `detach`, `#[private]`, `#[init]` re-initialisation, and the mocked VM's `MockAction` and storage. Checked NEAR protocol semantics: an atomic batch receipt (`storage_deposit` then `ft_transfer`) whose deposit returns to the gate on failure, the callback reading the batch's last result, storage staking checked at the end of each receipt, and function-call access keys.
- Rebuilt the deployable wasm (`make wasm-release` flags) and compared its NEAR code hash with the live testnet gate (read-only RPC).
- Read-only testnet RPC views: `view_access_key_list` for `gate-m3` and `agent`, `get_config` and `view_account` for `gate-m3`. No transaction was sent to any network. No key was used, printed or read. `.secrets/` and environment secrets were not read. Nothing was committed, pushed or posted.
- Wrote exploit tests that assert the required behaviour, so each fails while its finding is open, plus positive controls: `contracts/gate/tests/audit_a1.rs` (6 failing exploit tests, 5 passing controls). No JavaScript test was needed. No other file was changed.
- No text in the files read asked the auditor to change security behaviour. `fixtures/attacks/` was not opened, except that `fixtures/vectors/signed_mandate/erc191-valid-v27.json` is read as data by one control.

### Notes and fix direction (not applied)
- **A1C-01:** add `max_expiry_horizon_ns` to `Config` (validated, for example 1 hour to 30 days) and refuse funding of a **new** mandate whose `expiry_ns > now + horizon` (`expiry_too_far`). Top-ups are already bounded by expiry. For mainnet, use 24 hours. That turns the attack into one that must be repeated daily with fresh nonces and locked capital. Optionally also raise `min_funding` (see the config below). Format v1 needs no change: the check is gate policy.
- **A1C-02:** options, from simplest. (1) Accept in writing, keep a large free balance and watch it (see "Mainnet readiness"), and state in the README that anyone can top up the gate. (2) Do not anchor a refusal once a mandate's refusals exceed a small share of `max_orders_per_mandate`, so refuse unanchored with the event attributable (M3-07). This lowers storage per cycle, but weakens S4 for the agent's own refusals. (3) Charge storage to whoever creates it, as Q17 says: a payable `storage_deposit(mandate_hash)` by the buyer before funding, which 1Click-only buyers cannot do. A lead decision either way.
- **A1C-03:** if the lead takes a pause (Q36), keep it narrow. Add a `guardian: Option<AccountId>` in `Config` and a one-way `sunset()` callable only by it. Once set, `ft_on_transfer` refuses everything (returns the amount) and `purchase` refuses unanchored, while `refund` and the callbacks keep working. It can never be undone and cannot move funds. With A1C-01's 24-hour horizon, all escrow goes back to `refund_to` within a day of a sunset. Disclose it in the README. The guardian key is a named person's hardware wallet, never the deploy key. If no pause is taken, the caps below are the only damage limit, so keep them tiny.
- **A1C-04:** require, for an order delivered in `msg` on an agentless mandate, `order.amount == max_amount == amount of this transfer` (FORMATS.md 3 already calls `max_amount` the exact price for a person) and `order_id == nonce`. A front-runner then has to pay the full price for exactly the buyer's mandate. Document the remaining bounce (the buyer's delivery returned to the 1Click sender) as an **Assumption** checked in M5. Binding the order inside the signed mandate would close it fully, but needs a new format version and lead approval.
- **A1C-05:** reserve and allow two registrations per mandate (payee and `refund_to`), or register `refund_to` at funding time, when a failure can still hand the tokens back.
- **A1C-06:** write `scripts/mainnet-proof` (or a dedicated `scripts/mainnet-deploy.mjs`) for a person to run, with the checks listed under "Mainnet readiness". Never reuse `testnet-run.mjs`.
- **A1C-07:** before mainnet, run one testnet step that releases with prepaid gas set so that `gas_left()` is just above `gas_needed(true)`, against a payee whose transfer fails, then confirm `payout: Failed` and the budget restored. Repeat for a refund that closes the mandate.
- **A1C-08:** M6 checker: show "paid" only for `payout = Done`, and show `Failed` and `Pending` plainly.
- **A1C-09:** in `Config::validate`, require `network == "testnet"` iff `current_account_id` ends with `.testnet`, `network == "mainnet"` iff it ends with `.near`, and refuse implicit accounts.
- **A1C-10:** read `PROPTEST_CASES` in the gate property test as `crates/formats/tests/properties.rs` does, add direct-checkout funding and failed refund callbacks to the model, and run it with many cases in `make fuzz`.
- **A1C-11:** README trust statements. Optionally refuse a `registration_deposit` above the token's minimum.

## Prior findings re-verified
- **M3-01** (order only on the creating call): holds at `lib.rs:628-647`. The front-running residual that M3 itself named is A1C-04.
- **M3-02** (lifetime mandate cap): fixed for short expiries (`pc_a1_short_expiry_squat_frees_the_slots_after_expiry`). Not fixed for far expiries (A1C-01). M3 called that vector "temporary", but without a horizon it is permanent.
- **M3-03** (registration budget): one registration per mandate, released if it fails (`settle`). Holds. The side effect is A1C-05.
- **M3-04** (init): `#[private]` plus a predecessor check in the body. `#[init]` refuses re-initialisation. Holds.
- **M3-05** (storage bounded by balance): the invariant "free balance ≥ remaining reservation of all open mandates" holds by construction. Measured worst cases (1,902 B record, 336 B receipt, about 110 B `registered` entry) fit 2,400 B and 450 B. The leak is A1C-02.
- **M3-06, M3-07, M3-08:** hold (code read, tests pass). `transfer_succeeded` treats only `PromiseError::Failed` as failure. That is correct for near-sdk 5.30.1, where `promise_result_checked` returns `TooLong` only after a successful result.
- **M3-11:** partly; the residual is A1C-07.
- **M4-02:** the agent runs as a separate OS user (test passes). On chain the agent account's full-access key is still the shared operator key (read-only check). This is acceptable on testnet and must not carry over to mainnet (A1C-06).

## Items checked with no finding
- **S1 and S2 destinations:** the only `ft_transfer` and `storage_deposit` calls the gate creates go to the configured token, for the stored `payee` (release) or `refund_to` (refund). Both are fixed at funding from a verified signed mandate (`pc_a1_every_transfer_goes_to_the_token_for_payee_or_refund_to_only`, proptest).
- **Budget:** `funded ≤ max_amount` and `≤ max_escrow_per_mandate`. R7 needs `amount ≤ max_amount − spent` and `≤ escrow`. All arithmetic is checked or saturating where safe, with `overflow-checks = true` in release. `funded = spent + escrow + refunded` holds through failed payouts, failed refunds and races (proptest, M3 tests).
- **State before promises:** every write happens before the transfer promise. The gas check comes after the costly work and before the writes. A refused path creates no promise.
- **Callbacks:** `#[private]`, plus a predecessor check in the body. Exactly one promise result is read. The amount is restored into the bucket it came from. The order ID stays used, so its receipt is never overwritten.
- **Batch atomicity:** `[storage_deposit, ft_transfer]` sit in one receipt. On failure everything reverts, and the attached deposit comes back to the gate. The callback sees the result of the last action.
- **Callback gas share:** the callback gets 20 Tgas static plus all unused gas (weight 1). The transfers have fixed gas and no weight.
- **Signatures and formats:** canonical-only input (size, UTF-8, number scan, depth, re-serialisation equal to the input). Closed objects. ed25519 guard against small-order and non-canonical points and `S ≥ L`. ERC-191 low-s, `r` and `s` in range, `v` in {0, 1, 27, 28}, and the address taken from the recovered key. The NEP-413 payload layout is the tag, then the message, then the nonce, then the recipient (`mandate.gate`), then no callback URL.
- **EVM buyer through the gate** (nonce key `evm:`, no `purchase` path for the buyer itself): funds, releases to the agent's order and refunds only to `refund_to` (`pc_a1_evm_buyer_mandate_funds_pays_and_refunds`, using the committed vector as data).
- **Direct checkout by the buyer at the exact price** releases, and on an agentless mandate only the buyer's implicit account may call `purchase` (`pc_a1_buyer_direct_checkout_at_exact_price_releases`).
- **No panics on user paths:** every refusal returns. Only near-sdk argument decoding and the non-payable check can panic, and those write no state. Clippy `forbid` and the banned-call lint hold.
- **Logs and state:** no untrusted text. `sender_id` is never stored or logged. Events carry static reasons, hex, decimals and the canonical core.
- **Replay and squatting:** nonces are keyed by buyer, receipts by mandate plus order ID, and an expired mandate can never be funded again after close.
- **Agent key (S3):** enforced by the protocol, not the contract. The agent process is isolated by OS user (M4-02 fix). The agent checks its own key on chain before acting.
- **Reproducible build:** the code hash matches the live testnet deployment.

### One design change for both A1 audits
The lead chose two options on 7 November 2026: registration by a small Sampan relayer, and a one-way stop.
- **Register first.** `register_mandate(signed_mandate)` is payable. Whoever calls it (the Sampan relayer, or the buyer) attaches a deposit of `reservation_per_mandate()`: (2,400 + orders × 450) bytes of storage plus two token registrations. With 16 orders that is about 0.0985 NEAR. Any surplus goes back at once. A refused registration (stopped, bad signature, wrong network, gate or asset, expired, `lifetime_too_long`, `already_registered`, `nonce_used`, `mandate_cap`, `deposit_too_small`) returns the whole deposit, writes no mandate and emits `registration_refused`.
- **Payments name the mandate.** `FundingMsg` is `{"mandate_hash": …, "order": …}` or `{"signed_mandate": …, "order": …}`, with exactly one of the two. Only a zero amount, an unreadable or oversized message, an invalid mandate or an unknown mandate hands the payment back to the sender. Every other payment to a registered mandate is kept. What fits in escrow (the budget left, the per-mandate cap and the total cap) goes to escrow. The rest becomes **refund due**, payable to `refund_to` at any time. Nothing goes to escrow once the mandate has expired or the gate is stopped.
- **Unsigned orders inside a payment** (agentless mandates only) must ask for exactly `max_amount` and are released at most once per mandate (`not_exact_price`, `already_paid`). An order is never decided unless this payment put money in escrow. After the decision, this payment's escrow (all escrow, once released) moves to refund due. An order sent to an agent mandate is ignored (`order_ignored`) and the payment stays in escrow for the agent.
- **Lifetime.** `Config.max_lifetime_ns` (1 hour to 30 days, 24 hours on mainnet) bounds `expiry - now` at registration.
- **Closing.** A mandate closes once it has expired and holds no escrow, refund due or pending transfer. The registrant gets back the deposit minus the bytes it leaves behind (receipts and registered-account entries, counted in `kept_bytes`) and the registrations it used. The gate never pays for a stranger's storage.
- **Stop.** `Config.guardian` (optional) may call `stop()` once. After it, registrations and purchases are refused (`stopped`), payments to existing mandates are kept for the buyer, and refunds and callbacks work as before. Nothing can undo it, and it moves no funds. Calls from anyone else get `not_guardian`. On mainnet the guardian is a named person's hardware wallet, never the deploy key.
- **Init** is `#[private]` and refuses a network that does not match the account suffix.

Interface changes made several auditor tests call `register_mandate` before paying. Each of these mechanical changes is marked "Author adaptation after the A1 redesign" in the test file, and no assertion was weakened. Where a test asserted a reason that moved to registration (for example `wrong_network`), it now asserts that reason at registration, and `unknown_mandate` for the payment.
