### Notes and fix direction (not applied)
- **M4-02:** run the agent as a separate OS user or in its own container/namespace, with no read access to the operator's processes (`hidepid`, or a separate PID namespace), the repository's `.secrets/` or `$HOME`. Give it only its key file and `m4-state.json`, copied into a directory it owns. Give the agent account its own full-access key, not the parent's: create it, add the function-call key, then either delete the full-access key or keep it offline with the operator. Teardown then uses that separate key. Have the demo check the *whole* access-key list and refuse to run if any full-access key on the agent account is one the operator environment holds, or record the residual in writing. If the proxy may add credentials, limit the agent's egress to `rpc.testnet.near.org`. Restate the docs claim as "no secret in its environment, separate OS user" once that is true. For any later agent with a model, treat this as a blocker.
- **M4-03:** make `write-report.mjs` refuse to generate (exit 1) unless every row in all three files has `asExpected: true`, and print outcome columns from the recorded fields (`decision`, `anchored`, the error class), never from `expected`. For a protocol refusal, show the error with no transaction link. Give the `AddKey` transaction its own row.
- **M4-04:** classify on structured error types, not message regexes. near-api-js throws typed errors (`AccessKeyReceiverMismatchActionError`, `AccessKeyMethodNameMismatchActionError`, `AccessKeyDepositWithFunctionCallActionError`, `AccessKeyRequiresFullAccessActionError`, `NotEnoughAllowance…`, `AccessKeyNotFound…`). Also require that no transaction was created (no hash, and no `transactionResult` on the error). In `probe`, put the pre-flight refusal on a separate exit path so it can never be read as a protocol refusal, and skip the key check only on an exact `UNKNOWN_ACCESS_KEY` for the agent's own public key.
- **M4-05:** count a control as released only when the gate's `payout` event (or `get_receipt(...).payout`) is `Done`, and report a `Failed` payout separately.
- **M4-06:** `--teardown` should also delete `.secrets/agent-fc.key`, and the runbook should end with teardown. Optionally `setup.mjs` could give the mandate a short expiry (minutes, not 6 hours).
- **M4-07:** add a rule to `lint-banned.mjs` that loads every `page` (and any other text field) from `fixtures/attacks/**` and flags any tracked file outside `fixtures/attacks/` that contains a run of about 20 or more characters from it, printing only the file name and the fixture ID. Add the lint test the threat review lists.
- **M4-08:** allow a third label, for example `attack-in-mandate` with expected `release`, and publish "known misses: N (released by design, within the signed mandate)" next to the counts. At minimum, add one sentence to `docs/m4-testnet.md` and the README stating that limit.
